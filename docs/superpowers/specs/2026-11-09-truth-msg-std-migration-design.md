# MSG/END/STD 迁移到 truth 的设计

日期：2026-11-09。状态：已按用户确认路线实施。编译、map、工作台、MCP 和 GBK 补丁已接入；验证及实机待验项见 [集成记录](../../../deps/truth-integration-check-2026-11-09.md)。

## 1. 目标与验收结果

MSG、END、STD 从 thtk/Studio 旧方言完整迁移到 zero318 的 truth 生态。源码在 IDE 外也能直接交给同版本 truth 编译；用户和 agent 使用一致的版本、map 和诊断。完成切换时，安装包内工具可用，GBK 不退化，产品不再调用 thmsg/thstd。

END 包括结局和 staff，使用 trumsg 的 ending 模式，绝不能与关卡对话共用指令表。mission.msg 不在本次新增范围。ECL/ANM/DAT 后端保持原路线。

### 迁移覆盖基线

后端通道能力与完整可读名称资料分开记录，不能把 map 空缺等同于二进制必然不支持。迁移保留现有普通脚本通道范围，不借此新增游戏种类：

| 种类 | 本次目标作品 | 说明 |
| --- | --- | --- |
| stage MSG | TH06、07、08、09、10、11、12、128、13、14、143、15、16、165、17、18、185、19、20 | 早期作品原有语义辅助较少，仍保留基础编解码；新辅助按可用定义提供 |
| END/staff | TH10、11、12、128、13、14、15、16、17、18、19、20 | 按实际存在的 END 格式列举，不把旧 thmsg 宽泛接受的版本号当作存在结局文件 |
| STD | TH06、07、08、09、095、10、103、11、12、125、128、13、14、143、15、16、165、17、18、185、19、20 | 保留现有通道的基础范围；现有可读性支持主要在 TH14 以后 |

TH095/125 的 mission.msg、TH06–09 END、TH06NC 不在本次新增支持中。不存在对应 END 的外传不展示该模式。map 与工具的静态能力表按这些集合对齐，真实样本验证仍选择代表性格式世代及 TH19/20 差异，不要求每个作品全量实跑。若阶段 0 发现任何目标组合存在真实阻断，明确提交该组合及补救成本，不能静默缩减此表。

## 2. 已确认决策与替代方案

| 决策 | 已选路线 | 主要取舍 |
| --- | --- | --- |
| MSG/END/STD 后端 | zero318/truth | 放弃旧方言，获得原生 map、标签、控制流和统一语法 |
| 工具交付 | 固定版本随 Studio 分发 | 相比用户手动安装，增加平台构建责任，减少首次使用配置 |
| 旧 `.dmsg/.dstd` | 直接废弃 | 不保留双后端、不做转换器；旧编辑内容需要作者自行处理 |
| 汉化编码 | 必须保留 GBK | 先设计最小 truth 编码补丁，不以 thmsg 回退掩盖缺口 |

曾考虑继续用 thtk 名称翻译层、整体切到 truth、按格式混用。用户选择按格式混用，但 MSG/END/STD 内部不提供后端选择；ECL/ANM 的未来可配置性另行设计。

## 3. 推荐实现边界（待本文确认）

沿用 Rust 外部进程调用。truth 不链接进入 Tauri 主进程，不新增服务、数据库、任务队列或插件框架。新增 `modules/truth/` 只负责共用的进程参数、结果及诊断；保留 `modules/msg/` 和 `modules/thstd/` 的格式级协调职责，避免同时做大范围目录重命名。

前端仍只消费结构化数据。truth 源文件解析、map 选择和时序分析放 Rust；Monaco 负责高亮、提示、导航与展示。

## 4. 源文件与旧实现退场

建议采用明确的应用扩展名：

| 二进制/用途 | 新源码 | 后端模式 |
| --- | --- | --- |
| 关卡 `.msg` | `.msgspec` | trumsg |
| 结局/staff `.msg` | `.endspec` | trumsg --ending |
| `.std` | `.stdspec` | trustd |

这是 Studio 的命名约定，truth 本身不强制这些扩展名。正文保留原生 `meta`、`script`、常量、标签和控制流。默认名称建议先保留项目已使用的名字，在新 map 中补充新指令；不机械改成 zero318 的全部 snake_case。该命名建议与扩展名一起在设计审阅时确认。

旧 `.dmsg/.dstd` 不再参与构建、导出或专用语言支持，可作为普通文本打开；不批量删除用户文件，也不默默把它们当作 truth 源码。新文件另存，输出路径存在时沿用现有覆盖确认。迁移说明指导用户从原始 `.msg/.std` 重新反编译，已修改的旧源码自行对照迁移。

删除范围：MSG/STD 名称翻译、thmsg 编码桥接与 quirks、thmsg 签名覆盖、旧编译前检查、STD 跳转参数交换、原始 dmsg/dstd 导出、旧格式菜单和类型。有效的 UTF-8 文件读写、项目编码配置、通用诊断/输出结构继续复用。

## 5. 工具依赖与配置

固定基线见 [依赖清单](../../../deps/manifest.source.json)。最终构建包含编码补丁，补丁尚未实现。随包目录须同时放 `truth-core`、`trumsg`、`trustd`、许可文件和构建来源记录。

推荐用 Tauri `bundle.resources` 放置工具组，由 Rust resource_dir 定位并直接 Command 调用，保持包装程序要求的同目录关系；不改为每个 shim 单独重命名的 sidecar。Windows x64 作为首个安装包验收目标；Linux 当前开发环境验证同版本工具。其他发行目标只有在项目实际发布该目标时才要求对应原生产物，不凭空建立多平台 CI 矩阵。

应用配置建议添加 `truth_dir`；项目 `toolchain` 添加可选 `truthDir`，旧 JSON 缺字段默认空。优先级：单工具显式覆盖 > 项目 truthDir > 全局 truth_dir > 随包目录。thtkDir 仅用于 thecl/thanm/thdat。truth 路径失效时给出对应工具错误，不自动切回 thtk。

目标工具 ID：`thecl / trumsg / thanm / trustd / thdat`。旧配置中的 thmsg/thstd override 不映射为新程序路径、不自动执行；保存配置时的弃用键处理需明确测试。旧项目的 gameVersion、encoding、ECL mapPaths 继续保留。

构建版本识别采用随包来源记录，不能仅看 truth 的 Cargo version。没有批准自动下载、在线更新或 thtk 打包。

## 6. 编码前置条件

见独立的 [MSG/END 编码设计](2026-11-09-truth-msg-encoding-design.md)。默认 Shift-JIS，支持 GBK，解包/打包分别传入编码；保留现有项目编码的显式 UTF-8 能力，但不更改原作默认。编码补丁确认并验证前不能宣布完整切换完成。

## 7. map 与语言资料

- ECL 内置 map 不动；ANM 丰富 map 到 thanm 的适配留到 ANM 工作。
- MSG/END/STD 的有效定义必须合并固定 truth 核心版本规则、项目选择的 map 与源码 pragma。填补 zero318 gamemap 中间版本空缺；不能用一张新版表猜旧版。
- 保留原始编码签名；用户参数不包含 padding，字符串只算一个参数；显示枚举、参数类型、来源与中文说明。不要沿用逐字符计数的解析器。
- 名称、编码签名、行为文档分开维护；自有研究结论可以成为正式资料。END/MSG 分开命名空间。
- 新增的项目 map 配置建议为 `scriptMaps: { msg: string[], ending: string[], std: string[] }`，不复用当前专属 ECL 的 mapPaths。按列表顺序应用，后面的覆盖前面的；源码 pragma 按 truth 实际规则随后加载。
- 显式控制子进程的 TRUTH_MAP_PATH，避免开发者环境暗中增加 map。确定工作目录与 pragma 路径基准；反编译产生的引用必须持久、可在 IDE 外复现，不能指向临时目录。

### “语义定义”的具体范围

这里首先指**实际生效的指令定义**：目标游戏/脚本种类、opcode、名称与别名、用户参数个数和类型、枚举值、编码限制及 map 来源。它为补全、签名提示、静态导航和 agent 查询提供事实。truth 已经维护其编译需要的定义，Studio 不应再维护一份独立的编译器规则。

**领域文档**是另一层：参数名字、单位、行为、副作用、使用前提和示例，由社区资料及自有逆向成果整理。编译器接受五个参数，并不等于编译器能解释相机运动或证明效果正确。文档可按游戏/脚本种类/opcode 关联，不依赖显示名称作为主键。

**2026-11-09 用户决定：Studio 自己解析和管理 map，不为指令查询维护 truth 额外分支。** 不实现 truth JSON 查询命令，不增加独立 truth API 辅助程序，也不把 truth 链接进 Tauri。之前提出的两种复用 truth API 路线撤回。

落实边界：

1. 编译器按已有 CLI 编译/反编译，最终语法和编码有效性由真实编译检查判断。
2. Studio 的 Rust map 模块解析原生 map 的名字、签名属性、枚举与版本入口，合并项目覆盖，服务补全与 agent。
3. 固定基线缺少的内置签名，以有来源的版本数据补齐；不解析 truth Rust 源代码来动态猜规则，也不编写第二个类型检查器。数据变更对照少量真实编译用例验证。
4. 领域说明独立维护，先覆盖当前功能实际需要的指令；不要求所有 opcode 行为完全逆向后才能接入。
5. 编译器不认识、或资料确实缺失的条目按具体情况反馈；不向使用者展示普遍性的置信度警告。

GBK 是另一个已确认需求，保留独立编码设计；上述决定不授权为了 map 修改 truth。实现者若发现需要新增其它 truth 补丁，须说明必要性，不自动扩大下游维护范围。

## 8. 调用、诊断和界面

保留 `compile_msg_file/decompile_msg_file/compile_std_file/decompile_std_file` 的领域语义，更新请求类型，移除 withComments 这种旧输出翻译选项。MSG 类型显式区分 stage/ending；源码扩展名可以提供默认，二进制文件仍允许用户选择类型。

建议内部统一请求包含 kind、mode、inputPath、outputPath、version、有效 map 路径、游戏文本编码。复用已有 success/message/diagnostics/outputPath 结果；记录真实工具 trumsg/trustd。进程调用放后台，命令参数按 argv 构造。

truth 是 codespan 文本诊断，不能假定存在 JSON 诊断开关。先收集真实 stderr，保留完整输出，再提取可定位的主位置；无位置错误仍显示，不伪造行列。版本探测也不能沿用 thtk usage 文本解析。

所有相关入口一起切换：文件树图标与文件识别、标签状态、菜单、binary-script 视图、构建表单、设置、输出、问题面板和会话恢复。旧 `.dmsg/.dstd` 会话可作为普通文本恢复，不自动改变文件。

## 9. 语言服务与 agent

MSG/END/STD 共用 truth 词法规则，分别加载语义集合。首期包括高亮、注释/缩进、补全、悬停、参数提示、编译诊断和 STD 符号标签导航；无需完整 LSP。

保留基础时序阅读体验，但重新处理 script 块、绝对/相对时间、标签及循环。不能把结构化循环按旧行式解析器当作执行一次；静态时间不确定时显示源码位置和结构，不编造全局时间。只分析编写需求涉及的结构，不实现游戏 VM。

MCP 建议增加 MSG/STD 检查、编译、反编译与语义查询；END 复用 MSG 工具的 kind 参数。与 UI 调用同一 Rust 服务。检查仍编译磁盘文件到临时产物，不引入缓冲区同步协议。skill 教会 agent 使用当前版本、枚举、语言子集、检查工具和 GBK 选项，不能继续教它手工调用 thmsg。

## 10. 阶段与完成条件

1. 确认本文与编码设计；阶段 0 核对真实工具，细化 Studio map 服务接口。
2. 编码补丁和随包构建，完善来源记录。
3. map/配置/工具状态，MSG/END/STD 原生读写与结构化结果。
4. 编辑支持、时序/导航、MCP/skill，同批移除旧实现与失效测试。
5. 集中执行相关检查、代表性真样本往返、Windows 安装包检查，更新现状文档。

编译成功不能替代游戏内表现验收；不同编译器不要求无条件字节一致。往返检查比较必要的结构、文本、入口、跳转与元数据，字节变化需要解释。不得把 mock 调用通过作为后端验收。

## 11. 未包含的工作

不迁移 ECL/ANM，不新增 mission.msg，不建设自动更新、通用多后端、旧格式转换器、完整 LSP 或模拟器。不因审阅提出理论边角风险增加队列、数据库或恢复流程。
