# MSG / END / STD 编辑器 UI 接入

状态：用户已确认，已实施；基于已确认的 truth 外部 CLI 与 Rust 语义服务。

## 目标

打开二进制即可选择解包；打开原生源码即可检查、打包并调整输出。高亮、补全、参数提示、诊断、大纲和标签导航在实际编辑中可用，保留 ECL 工作流。

## 现状核查

- BinaryScriptView 的 MSG 已有编码与快捷解包，但没有高级入口和直接的 stage/ending 选择；STD 只有快捷反编译。
- MSG 有构建表单；registry 中 trustd 仍是 supportsBuildDialog=false 的占位项。
- Monaco 已注册三种 truth 语言与基础补全、悬停、参数提示、goto 定义。普通指令仍落入通用 identifier，缺少领域着色；补全主要是名字，尚无调用片段和源码结构补全。
- MonacoEditor 的自动诊断只调用 ECL 静态检查；truth 当前只在手动编译后拿到真实诊断。
- 右栏大纲与引用组件只接受 ECL；truth 只有基础时序列表。

## 方案比较

1. 只补按钮和表单：改动最少，但没有解决编辑中查错和导航问题。
2. 沿用工作台及 Rust 服务，补齐入口与 Monaco，使用真实 truth 做缓冲区检查：推荐；版本/map/编码与正式编译一致，主要新增一个检查 command。
3. 自建完整 truth parser/LSP：范围与维护成本明显扩大，本轮不采用。

## 界面与操作

二进制页沿用当前布局：

- MSG：关卡对话/结局选择、游戏文本编码、解包按钮、高级选项。
- STD：反编译按钮、高级选项。
- 高级表单覆盖操作模式、输出路径；MSG 另有 kind/encoding。版本与 map 显示项目生效设置，并提供进入项目设置的入口，复用既有默认值规则。

原生源码页在编辑区上方增加紧凑操作栏：

`MSG / END / STD    项目版本    [检查] [打包] [构建选项…]`

快捷操作与菜单、二进制页调用同一套 actions，显示执行状态，成功时刷新产物，失败时定位问题。编译前沿用现有脏文件保存。

## Monaco

- 使用工作台现有 token 和主题，区分指令调用、原始 ins_N、标签、时间、枚举、关键字、字符串和注释。
- 补全提供指令调用片段及参数占位符、枚举、常量和当前 script 标签；签名识别正确跳过字符串中的逗号和嵌套表达式。
- 注册 DocumentSymbol、标签定义/引用，右栏显示 truth 的 script/标签与源码位置；不虚构资源引用或运行结果。
- map 查询失败应有可见的状态说明，避免用户看到空补全却不知道原因。

## 检查接口（已确认）

新增 Tauri `check_truth_source(inputPath, scriptKind, sourceText)`：检查当前缓冲区，包括尚未保存的编辑。Rust 使用当前项目版本、有效 map 和编码；将 UTF-8 缓冲区写到原文件同目录的临时原生源码，调用现有 truth 编译服务输出到临时文件，完成后清理。保持相对 pragma 的目录语义；诊断中的临时源码路径映射回编辑中的原文件，返回既有结构化诊断。

手动检查立即调用；输入停顿后触发自动检查。前端复用诊断计时器，并以模型版本丢弃过期结果，关闭模型清除标记。没有持久任务队列、完整 LSP 或新 parser 依赖。目录不可写时明确报错，不静默检查旧磁盘内容。

简单替代是只在保存后检查：不需要缓冲区临时源码，但未保存内容不会有真实语法诊断。推荐缓冲区检查，以满足用户对 Monaco 编辑体验的要求。

## 实施与验证

按工具表单/actions → 源码操作栏/二进制入口 → Monaco providers/右栏 → 检查服务及诊断接线推进。按层保持 Vue 展示、Rust 重逻辑、外部 truth 编译边界。

已有检查：typecheck、前端测试、构建、受影响 Rust 测试。新增用例仅覆盖具体行为：STD 表单执行和输出路径、调用参数中的字符串/嵌套表达式、script 内标签导航、未保存错误经过真实 truth 定位且不改原文件。UI 最多截图检查，不跑浏览器自动交互。Windows 实机和游戏效果另记。
